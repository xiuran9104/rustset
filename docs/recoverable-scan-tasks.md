# 可恢复扫描任务

扫描任务和资产基线核查统一写入 `infra_task`，由网关进程内的 Worker 从数据库领取执行。API 提交成功只表示任务已经持久化排队；执行状态通过任务列表查询。

## 状态与恢复

- `queued`：等待领取。
- `running`：Worker 已领取并持有执行租约。
- `retrying`：执行失败或租约过期，等待下一次尝试。
- `completed`、`failed`、`cancelled`：终态。

Worker 使用 `FOR UPDATE SKIP LOCKED` 并发领取任务，每次领取增加 `attempt_count`。执行期间续租；进程退出或失去心跳后，过期租约会回到重试队列，达到 `max_attempts` 后转为失败。重试采用最长约五分钟的指数退避。任务的目标和端口保存在 `payload` 中，因此网关重启后可以恢复执行。

客户端可传入最多 128 字符的 `idempotencyKey`。同一租户使用相同键重复提交时返回原任务 ID。`maxAttempts` 范围为 1–20，`timeoutSeconds` 范围为 1–86400；未提供时使用安全默认值。

取消接口会立即终止排队任务；正在运行的任务在当前探测批次结束后停止。失败或取消的扫描、巡检任务可以通过重试接口重新排队。

## 并发与网络范围

`SCAN_WORKER_CONCURRENCY` 控制单个网关进程同时执行的任务数，默认 4，允许 1–32。每个扫描任务内部最多并发 64 个 TCP 连接，单次连接超时 800 毫秒。

扫描接口只接受明确的 IPv4 或 IPv6 地址，每个任务最多 64 个，不展开 CIDR 或地址区间。端口策略包括常用端口、1–1000 加常用高端口、全端口；自定义触发接口会校验并去重端口。

多个网关实例可以共用队列表。任务租约可防止正常情况下的重复领取；探测结果和风险写入使用稳定键或 UPSERT，使租约恢复后的重复执行保持幂等。
